# Shepit: plan

Personal voice dictation for one Mac. Hold a key, speak Ukrainian or English, release, and
clean, app-appropriate text lands in the focused field. Built for dictating prompts to AI
tools (Claude Code in Terminal, Claude.app, ChatGPT, claude.ai in the browser), but usable
anywhere text goes. Single user, no landing page, no accounts, no distribution.

Status: approved 2026-10-24 with the decisions in section 12. Phase 0 tooling and Phase 1 code written the same day; see `docs/DECISIONS.md` for what was measured and what still needs a verification session.

## 1. Decisions at a glance

| Topic | Decision | Why |
| --- | --- | --- |
| Platform | Native macOS 26 app, Swift 6, SwiftUI + AppKit | Menu bar, floating panel, Accessibility API and global hotkeys all need AppKit. One machine, so no need to support older macOS. |
| Speech to text | On-device. Candidate A: NVIDIA Parakeet TDT 0.6B v3 via FluidAudio. Candidate B: Whisper large-v3-turbo via WhisperKit. Chosen by a short benchmark on your voice (Phase 0). Pluggable behind one protocol. | Apple's new `SpeechTranscriber` has no Ukrainian (checked on this Mac). Parakeet v3 lists Ukrainian with 6.8% WER on FLEURS and is 10x+ faster than Whisper. Whisper is the safer bet for mixed Ukrainian/English speech. |
| Text formatting | Claude, via your local Claude Code CLI running as a persistent headless worker (Haiku by default). Direct Anthropic API as an optional second backend. Passthrough when Claude is unreachable. | Uses your subscription, no API key, no hosted model. Measured 1.1-1.3 s per turn on this Mac with a trivial prompt; 1.5-2.5 s expected with a real one. |
| Hotkey | Configurable in Settings. Default: Right Option (⌥) held = push to talk, double tap = hands-free. Fn works only after the system Fn setting is changed to "Do nothing". | Your Fn key is set to "Change input source" (switching uk/en layouts), so Fn hold would fight with that. |
| Insertion | Paste (clipboard save and restore) by default, Accessibility `AXSelectedText` where it is verified to work, keyboard typing as last resort. Never auto-submit. | Paste works in Terminal, Electron and browsers. AX is cleaner but fails in many apps. |
| Learning | No model training. A local SQLite store of dictations, corrections, a personal dictionary, per-app style rules, few-shot examples, and a periodic "distill my style" job run by Claude. | This is what "learns how you write" means in Wispr Flow too: post-processing conditioned on your history. |
| Widget | Draggable floating button, AssistiveTouch style: snaps to screen edges, fades when idle, expands while listening, remembers position. Non-activating so the target app keeps focus. | Your explicit requirement. Wispr's bar is fixed at the bottom center. |
| Storage | `~/Library/Application Support/Shepit/` (SQLite via GRDB, models, logs). Dictionary and profiles exportable as JSON. | Plain files that are easy to inspect and get backed up with the home folder. |
| Build | Xcode project generated by XcodeGen from `project.yml`, core logic in a SwiftPM package with tests, signed with your Apple Development identity. | Keeps the repo text-only and the build scriptable. A stable signature means macOS does not re-ask for Microphone and Accessibility after every rebuild. |

## 2. What Wispr Flow does, and what we copy

Studied: wisprflow.ai/developers, /demo, /why-flow, plus their help center.

Their core loop: hold Fn, speak, release, text appears. Hands-free on Fn+Space (or double tap).
Command Mode on Fn+Ctrl edits selected text by voice. A "Flow Bar" shows listening and
processing states. Formatting is automatic: filler words and self-corrections removed
("5 pm, actually 6" becomes "6 pm"), lists become lists, emails get greeting and sign-off, tone
follows the app. A personal dictionary and screen context spell names and terms (Vercel,
Supabase, camelCase, snake_case). Snippets expand a spoken cue into stored text. Language is
auto-detected per utterance, 100+ languages, switching mid-stream allowed. They claim 90%
zero-edit accuracy and a model stack that is retrained from user corrections.

We copy: push to talk and hands-free, auto-detected uk/en, filler and self-correction cleanup,
per-app formatting, dictionary, snippets, history, learning from corrections, command mode
(later phase).

We change: the widget is draggable; there is a "prompt mode" that structures long dictations
into a well-shaped prompt for AI tools; formatting runs on Claude through your subscription;
everything except the formatting call stays on the Mac; no cloud speech recognition by default.

## 3. Facts about this Mac (measured 2026-10-24)

- MacBook Pro, Apple M1, 8 cores, 16 GB RAM, macOS 26.5.2, Xcode 26.6, Swift 6.3.3.
- Claude Code CLI 2.1.310 at `~/.local/bin/claude`, logged in. No `ANTHROPIC_API_KEY`, no `ant` CLI.
- `whisper-cli` (whisper.cpp 1.9.1) and `ffmpeg` installed via Homebrew; no models downloaded.
- No Node, Python 3.9 only. Rules out the Agent SDK packages; the CLI is the integration point.
- Four Apple Development signing identities in the keychain.
- Terminal: Apple Terminal (where Claude Code runs). Relevant apps installed: Claude.app,
  ChatGPT.app, Google Chrome, Safari, Telegram, Visual Studio Code, Xcode.
- Fn key behaviour: "Change input source".
- Apple speech frameworks on this machine:
  - `SpeechTranscriber.supportedLocales`: 30 locales, no `uk`. English installed.
  - `DictationTranscriber.supportedLocales`: 54 locales, includes `uk-UA` (legacy dictation
    engine; quality for Ukrainian is not competitive, kept out of scope).
  - `SFSpeechRecognizer(uk-UA)`: available, but `supportsOnDeviceRecognition == false`.
- Headless Claude Code, Haiku, trivial prompt:
  - one-shot `claude -p`: 2.3-6.0 s wall clock (process start plus request);
  - persistent `--input-format stream-json` worker with `--setting-sources "" --strict-mcp-config --tools ""`:
    1.1-1.3 s per turn, 624 tokens of system prompt, no MCP servers or tools loaded.
  - Messages piped to the worker while a turn is running are merged into the next turn. The
    app must send one message and wait for its `result` before sending the next.
  - `--bare` is faster to start but does not use the subscription login, so it is not usable.
- Parakeet TDT 0.6B v3 model card: 25 European languages including `uk`; WER uk 6.79% (FLEURS),
  5.10% (CoVoST); en 4.85% / 6.80%. Automatic language detection, punctuation and
  capitalization in the output. Nothing published about mixed-language utterances.
- FluidAudio (Swift, macOS 14+): `AsrModels.downloadAndLoad(version: .v3)`, `AsrManager`,
  `SlidingWindowAsrManager` for streaming, Silero VAD v6 via `VadManager`. ~190x real time on M4
  Pro; no M1 figure published. The benchmark also covers the newer
  `.ultra` Parakeet variant.
- WhisperKit now ships inside `argmaxinc/argmax-oss-swift` (products `WhisperKit`, `TTSKit`,
  `SpeakerKit`). Recommended model on macOS: `large-v3-v20240930_turbo`.

## 4. Architecture

```
 hotkey / widget gesture
        │
        ▼
 ┌──────────────┐   16 kHz mono   ┌──────────────┐  raw text   ┌────────────────┐
 │ AudioCapture │ ───────────────▶│ SpeechEngine │ ───────────▶│  Formatter     │
 │ AVAudioEngine│   + VAD events  │ Parakeet /   │             │  Claude Code   │
 │ + Silero VAD │                 │ WhisperKit   │             │  worker / API /│
 └──────────────┘                 └──────────────┘             │  passthrough   │
                                                               └───────┬────────┘
 ┌──────────────┐  app, title, URL, field text, selection                │ final text
 │ ContextProbe │ ─────────────────────────────────────────────────────▶ │
 │ NSWorkspace  │                                                        ▼
 │ + AX API     │                                               ┌────────────────┐
 └──────────────┘                                               │ TextInserter   │
                                                                │ AX / paste /   │
 ┌──────────────┐  dictionary, profiles, examples                │ type           │
 │ LearningStore│ ◀──────────────────────────────────────────── └────────────────┘
 │ SQLite       │  events, corrections (read-back diff, "fix last")
 └──────────────┘
```

Components (each a Swift type behind a protocol, so engines and backends can be swapped):

1. HotkeyController: `NSEvent` global monitor for `.flagsChanged` (modifier hold detection,
   press/release timing, double-tap), plus the KeyboardShortcuts package for combo shortcuts.
   Escape cancels a recording.
2. AudioCapture: `AVAudioEngine` input tap, converted to 16 kHz mono Float32. Starts on key
   down, stops on key up. Level meter for the widget. Silero VAD (FluidAudio) for hands-free
   auto-stop and to drop empty recordings before they reach the recognizer.
3. SpeechEngine protocol: `transcribe(samples) async throws -> Transcript` where the
   transcript carries text, detected language, and timing. Implementations: `ParakeetEngine`
   (FluidAudio), `WhisperKitEngine`. Model kept loaded; optional unload after N idle minutes
   (16 GB machine).
4. ContextProbe: frontmost app bundle id and name (`NSWorkspace`), focused window title, URL
   for browsers (AX `AXDocument`/`AXURL` on the web area), focused element role, its value and
   selection range, text before the caret (last ~500 chars), selected text, and whether secure
   input is on (`IsSecureEventInputEnabled`, in which case nothing is inserted).
5. Formatter protocol: `format(request) async throws -> FormattedResult`. Implementations:
   - `ClaudeCodeWorker`: one long-lived `claude -p --input-format stream-json
     --output-format stream-json --verbose --model haiku --tools "" --setting-sources ""
     --strict-mcp-config --no-session-persistence --system-prompt-file <profile>` process in an
     empty working directory. One request in flight at a time. Recycled after ~25 turns or
     15 idle minutes; a warm standby process is started before the old one is retired so the
     restart costs nothing on the hot path. Output is JSON (via `--json-schema` if it works with
     stream-json, otherwise a JSON instruction in the prompt with a tolerant parser).
   - `AnthropicAPIFormatter`: direct Messages API with the official HTTP shape, prompt caching
     on the system prompt. Only if you add a key later.
   - `PassthroughFormatter`: returns recognizer output with minimal cleanup. Used when Claude
     is unreachable, in Raw mode, and on the fast path (below).
6. TextInserter: per-app strategy, learned and stored. Try AX (`kAXSelectedTextAttribute` on
   the focused element, then read back to verify), else paste (snapshot pasteboard, write text,
   post ⌘V via `CGEvent`, restore after 300 ms unless the pasteboard change count moved on),
   else `CGEventKeyboardSetUnicodeString` typing. Trailing newline stripped for terminals. If no
   editable element is focused, the text goes to the clipboard and the widget says so.
7. LearningStore: SQLite (GRDB). Tables: `dictations` (raw, formatted, final, app, title, url,
   language, mode, engine, timings), `dictionary` (term, variants, language, scope, source,
   weight), `profiles` (bundle id or URL pattern -> mode, style rules, examples), `snippets`
   (trigger phrases -> text). Correction capture: after insertion, re-read the element value at
   +3 s, +15 s and on focus change; if only the inserted region changed, store the final text
   and extract word-level diffs as dictionary candidates. Where AX read-back is impossible
   (terminals, some Electron fields), "Fix last…" in the widget menu opens a popover to edit the
   last result and saves the diff.
8. DictationSession: the state machine idle -> recording -> transcribing -> formatting ->
   inserting -> done/failed, with cancellation at every step. Drives the widget and the menu
   bar icon.
9. UI: menu bar `NSStatusItem` (state icon, menu). Floating widget (`NSPanel`,
   `.nonactivatingPanel`, `.borderless`, level above normal windows, joins all Spaces and
   full-screen apps, never becomes key). Settings window and History window in SwiftUI.

## 5. Formatting behaviour

### Modes

- Clean (default): remove fillers and false starts, apply self-corrections, punctuate, split
  into paragraphs, turn spoken enumerations into lists. Keep wording, meaning, and language.
  Never answer the content, never add facts.
- Prompt: clean, then shape as a prompt for an AI: short paragraphs or bullets for goal,
  context, constraints and expected output, only from what was said. Automatic when the target
  is an AI tool and the dictation is longer than ~40 words; forced or suppressed from the widget
  menu or with a modifier while pressing the hotkey.
- Raw: recognizer output only, no Claude call.
- Command (Phase 4): hotkey variant where the speech is an instruction applied to the selected text
  ("make it shorter", "translate to English") and the result replaces the selection.

### Language rules

- Output language is the spoken language; the recognizer's language id is passed as a hint,
  Claude confirms it.
- Mixed speech: Ukrainian sentence with English product names, identifiers, file paths, CLI
  flags stays Ukrainian with those terms in Latin script and canonical spelling
  (`handleSubmit`, `UserService.swift`, `git rebase`), using the dictionary and the on-screen
  context to fix transliterations the recognizer produced.
- No translation unless dictated as a command ("напиши англійською: …").
- Ukrainian typography: apostrophe and quotes per profile; dash style is a setting, default "-".

### Fast path

Dictations under ~8 words with no structure cues in a non-AI target skip Claude and insert the
recognizer's punctuated output directly (sub-second). Everything else goes through Claude.

### Per-app profiles (defaults, editable)

| Target | Detected by | Mode | Style rules |
| --- | --- | --- | --- |
| Claude Code in Terminal, iTerm2, Ghostty, Warp | terminal bundle id + window title containing "Claude" | Prompt | Plain text, no markdown headers, "-" bullets, identifiers and paths verbatim, no trailing newline, never press Enter |
| Claude.app, ChatGPT.app; claude.ai, chatgpt.com, gemini.google.com in a browser | bundle id / URL | Prompt | Markdown lists allowed, short paragraphs |
| VS Code, Cursor (chat panel) | bundle id | Prompt | Markdown, code identifiers in backticks |
| Telegram, Slack, Messages | bundle id | Clean | Casual, short, no period on one-liners, emoji only if spoken |
| Mail; Gmail in a browser | bundle id / URL | Clean | Paragraphs; greeting and sign-off only when dictated |
| Notes, Obsidian, Notion, Google Docs | bundle id / URL | Clean | Lists when enumerating, paragraphs otherwise |
| Everything else | default | Clean | Neutral |

### Prompt to Claude

A stable system prompt per profile (cacheable): role, the rules above, the style rules, the
output JSON shape. The per-dictation user message carries: app, title, URL, text before the
caret, selected text (Command mode), mode, language hint, the ~50 most relevant dictionary
entries (by app scope and recency), 3-5 recent accepted examples for this app chosen by token
overlap with the transcript, the snippet triggers, and the raw transcript. Output:
`{"text": …, "language": "uk|en|mixed", "snippet": null | "<name>", "new_terms": […]}`. Snippets
are expanded locally from the name, so Claude never has to reproduce long stored text.

## 6. Learning

1. Every dictation is stored with its raw and formatted text and context.
2. Corrections are captured by AX read-back where possible and by "Fix last…" everywhere.
3. A correction that changes a word the same way twice, or once with manual confirmation,
   becomes a dictionary entry with its misheard variants. Entries can be global or scoped to an
   app. The dictionary is injected into the Claude prompt; if FluidAudio exposes its CTC
   vocabulary boosting in a release, the same list biases the recognizer as well.
4. Accepted (raw -> final) pairs feed the few-shot examples per app.
5. A distillation job (on demand, or weekly) sends the last N pairs per app to Claude Code with
   Sonnet and asks for at most 10 style rules per profile. The rules are shown in Settings and
   can be edited or discarded. This is how the formatting drifts toward your own habits.
6. Stats view: dictations per day, median latency per stage, edit rate per app (the local
   equivalent of Wispr's zero-edit score).

## 7. Widget and menu bar

Widget states and gestures:

- Idle: 40 pt circle at ~55% opacity, snapped to the nearest left or right screen edge,
  position remembered per display. Hover brings it to full opacity.
- Listening: expands into a pill with live level bars and elapsed time.
- Processing: shimmer, label "formatting".
- Done: checkmark and the first words of the inserted text for ~2 s; click opens the history
  entry.
- Failed: shake and a one-line reason (no text field focused, Claude unreachable, secure input
  active). Text is on the clipboard when insertion was impossible.
- Drag to move (a movement threshold separates drag from click). Click toggles hands-free.
  Press and hold is push to talk with the mouse. Right click: mode (Clean / Prompt / Raw),
  language lock (Auto / UK / EN), Fix last…, History, Hide widget, Settings.

Menu bar: state icon; Enable/Disable, current mode, Show/Hide widget, History, Dictionary,
Snippets, Settings, Quit. Settings: hotkeys, recognizer and model, formatter backend and model,
profiles editor, dictionary, snippets, input device, widget options, launch at login
(`SMAppService`), privacy (what context is sent, history retention).

## 8. Permissions, signing, install

- Microphone (`NSMicrophoneUsageDescription`), Accessibility (AX reads, AX insertion, posting
  ⌘V, global key monitors). Input Monitoring may be requested as well for the modifier-hold
  monitor; the first run will show which.
- Sign every build with the same Apple Development identity and bundle id so TCC grants
  survive rebuilds. `make install` copies the Release build to `/Applications`.
- Launch at login via `SMAppService`. Logs via `OSLog`, subsystem `shepit`.
- Privacy: audio never leaves the Mac. The transcript and a small context (app, title, URL, text
  before the caret) go to Anthropic through Claude Code. Context sharing can be narrowed in
  Settings. History is local and can be purged.

## 10. Phases, acceptance, estimates

Estimates separate agent coding time from verification sessions. The sessions are the
serial resource here (one Mac, one microphone, permission prompts and quality judgments that
only you can do). A verification session is 20-40 minutes with you at the keyboard.

### Phase 0: benchmark and worker spike

- `spike/shepit-bench`: SwiftPM CLI that runs Parakeet v3, Parakeet ultra and WhisperKit
  large-v3-turbo over a folder of WAV files and prints text, detected language, latency and
  peak memory on this M1.
- You record ~20 utterances once (Ukrainian, English, mixed with identifiers and file names,
  one or two with self-corrections). A record script is provided.
- Claude Code worker driven with a realistic ~1.5K-token prompt: latency, whether
  `--json-schema` works with stream-json, token overhead per turn.
- Output: `docs/DECISIONS.md` with the chosen engine and backend, plus the measured numbers.
- Estimate: 1.5-2.5 h coding and runs; 30-45 min of your time. Unknown: whether Parakeet keeps
  English identifiers inside Ukrainian speech in Latin script, or whether that must be left to
  Claude.

### Phase 1: the loop works end to end

Menu bar app, Right Option push to talk, capture, chosen recognizer, Claude worker in Clean
mode with a generic profile, paste insertion, widget with idle/listening/processing/done,
history in SQLite, logging.

Accepts when: a Ukrainian and an English prompt dictated into Claude Code (Terminal),
Claude.app and claude.ai in Chrome land correctly; release-to-insert under 3 s for a 10-15 s
utterance; Microphone and Accessibility grants survive a rebuild.

Estimate: 3-5 h coding (three parallel tracks: shell and widget; audio and recognizer; worker
and inserter), two verification sessions. Unknown: first-run permission flow quirks on macOS 26.

### Phase 2: context, profiles, modes

ContextProbe, per-app profiles with Prompt mode, fast path, hands-free with VAD auto-stop, Raw
mode, AX insertion with per-app strategy learning, snippets, Settings window, launch at login,
secure-input guard, pasteboard restore.

Accepts when: the same dictation produces terminal-style plain text in Claude Code and markdown
in claude.ai; a 5-word Telegram message inserts without a Claude call; hands-free stops itself
after silence; no clipboard content is lost across 20 dictations.

Estimate: 4-6 h coding, two to three sessions. Unknown: AX behaviour of Chrome and Electron
fields, which can push insertion to paste everywhere. Paste is an acceptable fallback, just less elegant.

### Phase 3: learning

Correction capture, dictionary with auto-promotion and editor, few-shot retrieval, distillation
job, "Fix last…", stats.

Accepts when: a term corrected twice is spelled right on the third dictation; the profile rules
list changes after a distillation run and the change is visible in output.

Estimate: 3-5 h coding, one session, then a week of normal use before tuning thresholds. The
week is calendar time, not work.

### Phase 4: polish and extras

Command mode, partial transcript in the widget while speaking, sounds, multi-display edge cases,
model unload policy, export/import, optional direct API backend, optional cloud recognizer
fallback behind the same protocol if the benchmark shows local Ukrainian is not good enough.

Estimate: 3-5 h coding, one to two sessions.

### Total

Coding 15-24 h of agent time. Wall clock 3-5 working days, set by how many verification
sessions fit in a day. Stalls counted separately: model downloads (~1-2 GB), Xcode first build,
any TCC permission that needs a restart. Only you can do: grant permissions, record the test
set, judge Ukrainian quality, try it in your daily apps.

## 11. Risks

| Risk | Mitigation |
| --- | --- |
| Recognizer transliterates or drops English terms inside Ukrainian | Dictionary and screen context in the Claude step; WhisperKit as alternative engine; cloud recognizer fallback kept possible behind the protocol (off by default, sends audio out) |
| Claude step too slow for short messages | Fast path without Claude; Haiku; persistent warm worker; direct API backend option (~0.5-1 s) |
| Claude Code CLI flags change in an update | A worker smoke test runs before any CLI upgrade; fallback to one-shot `claude -p`; passthrough when the worker fails |
| Subscription quota | Each dictation costs roughly 1-3K tokens on Haiku; usage shown in Stats from the worker's `usage` fields; API backend if it ever matters |
| TCC re-prompts after rebuilds | Stable signing identity and bundle id from day one |
| Fn conflicts with layout switching | Right Option default; Fn available after changing the system setting |
| Clipboard clobbering | Snapshot and restore with change-count check; AX insertion where verified |
| Password fields | Secure input detection; nothing inserted, nothing stored |
| Memory on 16 GB | One recognizer model resident (0.6-1.6 GB); optional idle unload |
| Whisper hallucinating on silence | VAD gate, minimum speech duration, empty-result filter |
| Widget misbehaving across Spaces and full-screen apps | Panel collection behaviour set for all Spaces and full-screen auxiliary; tested in Phase 1 |

## 12. Decisions taken

Answered 2026-10-24:

1. Hotkey: configurable in Settings. Default Right Option hold, double tap for hands-free.
   Fn is offered as an option with a note that the system Fn setting must be "Do nothing".
2. Formatting backend: Claude Code worker on the subscription. The direct API backend stays
   a documented option, not built in the first phases.
3. Speech recognition: local only. No cloud recognizer, not even as a fallback, until the
   local benchmark says otherwise.
4. Name "Shepit", bundle id `com.themarchenko.shepit`.
